# 个人声音朗读项目报告

日期：2026-11-16
范围：目标、方案、实施结果与用户评价

> 本报告记录开发阶段结果。阅读器代码及不含模型的安装包正在作为 0.2.0 发布；发布状态以 [GitHub Releases](https://github.com/sssxzxz/readerzx/releases) 为准。

## 一、总体结论

本阶段已完成本机阅读器中的个人声音试听、整本书后台生成、已生成内容点读和音色库功能。预生成音频的播放响应较快，但新内容的语音合成速度仍明显低于用户期望。

**用户对当前结果的最新评价：**

> 音色尚可，但是太慢了。

因此，当前状态应记录为：**功能集成已完成，体验目标部分达成；音色基本可接受，生成速度未达标，整体方案尚未满足用户要求。** 不能以缓存播放很快或自动化测试通过，代替对生成速度的验收。

## 二、用户目标与约束

1. 使用自己的声音朗读中文书籍，保存后可以跨书复用。
2. 希望生成速度接近本机 Windows TTS，减少等待。
3. 提前生成整本书，之后点击正文即可快速朗读。
4. 不必等待全书完成，已经生成的部分可以先播放。
5. 生成整本书之前，可以用模型合成一段新文字试听效果。
6. 后续可以保存、命名和选择多个音色。
7. 本机没有独立 GPU，优先使用本地 CPU 方案。
8. 执行顺序为“先试轻量直接克隆，再决定是否花钱训练”。曾讨论一次性云端训练后下载使用，训练预算上限为 500 元，但本阶段未采用该路线。

评价需要分别看三个结果：**声音是否像本人、点击后多久开始输出声音、生成一分钟朗读需要多久。** 这三项不能互相替代。

## 三、提出并采用的方案

### 1. 本地轻量直接克隆

采用 **ZipVoice-Distill INT8 + sherpa-onnx** 在本机 CPU 上生成语音，使用用户提供的录音及对应文字作为克隆条件。

复用了本机 Aixora 文件夹中的 Python 和音频转换程序，另行准备并接入轻量模型运行环境。当前生成流程由阅读器调用，不要求用户手动操作 Aixora 界面。

该方案没有训练独立的个人声音小模型。音色库保存的是供基础模型复用的录音副本、对应文字及音色信息，仍依赖基础模型进行合成；它也不是安装到 Windows 系统中的 TTS 语音包。

### 2. 按句预生成并保存

阅读器提取全文，建立句子与正文位置的对应关系，后台逐句生成音频。每句完整保存后即可播放。

点击已生成的句子时，直接读取本地音频；点击尚未生成的位置时，优先生成该句及邻近内容。任务可以暂停、继续，关闭应用后保留已完成成果。

这一设计解决了重复播放时的等待，**没有把新内容合成本身加速到 Windows TTS 的水平**。

### 3. 音色库与试听

已保存“我的声音”，并提供导入、命名、选择、试听和删除音色的界面。试听会用所选音色合成输入的新文字，并非直接回放原始录音。

同一本书可以保存不同音色的音频。音色改名不会触发重新生成；更换录音时另存为新音色，保留旧音频版本。

## 四、实际结果

### 1. 音色与速度

| 指标 | 当前结果 | 如何理解 |
| --- | --- | --- |
| 音色评价 | 用户评价“音色尚可” | 基本可接受，不代表整体方案满意 |
| 已生成内容点读响应 | 最新五次测量约 0.096～0.104 秒 | 已有音频的播放响应，不包含生成等待 |
| 阅读器实际合成速度 | 57.56 秒音频生成耗时 45.03 秒 | 共 11 句，包含声音引擎冷启动 |
| 换算每分钟音频的生成耗时 | 约 46.94 秒 | 当前阅读器逐句生成流程的实测值 |
| 冷启动后首句生成完成 | 约 6.54 秒 | 首句完成时间，不是扬声器出声延迟 |
| Windows 康康生成速度 | 约 0.23 秒生成一分钟音频 | 同样文字、三次测试的中位数，不含扬声器延迟 |

个人音色的单位音频生成耗时，约为本次 Windows 康康测试的 **200 倍**。这说明用户提出的“像 Windows TTS 一样快”的生成目标尚未实现。

按当前样本粗略线性估算，生成 1 小时音频约需 47 分钟，生成 10 小时音频约需 7.8 小时。**这些只是样本外推，不是整书实测或耗时承诺**；句子长度、文本、电脑负载和启动开销都会影响结果。

点读响应的测量范围为软件点击请求到电脑音频输出出现信号，采用 10 毫秒采样块；没有测量实体鼠标操作到空气中声音的完整延迟。

### 2. 已验证的功能

- 部分音频生成完成后即可播放。
- 点击尚未生成的后部句子，会优先处理该位置。
- 暂停、继续、播放端变速和停止可用；变速保留音高，不重新生成。
- 关闭重开后可以复用已生成片段；合成程序不可用时，缓存音频仍能播放。
- 不同音色的音频相互隔离；书籍内容变化后，不会误用旧版音频。
- 失败句子可重试，损坏片段可修复；模拟磁盘不足时会暂停并保留成果。
- 删除音色后，原录音不变，应用保存的录音副本清理，已生成书籍音频仍然保留。
- TXT、EPUB、FB2 和含文字的 PDF 已实际验证；EPUB、FB2 验证了跨章节连续朗读。
- 原有翻页、语音控制、全屏等功能通过回归检查，类型检查与构建通过。

### 3. 连续播放验证

修复了窗口最小化后，后台限速导致句间停顿的问题。最终测试结果为：

| 项目 | 结果 |
| --- | --- |
| 音频总时长 | 1800.02 秒，约 30 分钟 |
| 片段数量 | 995 个 |
| 播放顺序 | 全部按顺序完成，无漏句或重复 |
| 最大额外衔接间隔 | 48.77 毫秒 |
| 95% 额外衔接间隔 | 不超过 19.57 毫秒 |
| 结束状态 | 正确显示播放完成 |

此项测试使用真实生成的音频，但为避免长时间打扰，**测试输出静音**。它验证播放顺序、完成状态和软件衔接，不等于对 30 分钟音色、发音及听感的人工验收。

## 五、用户评价与目标达成情况

| 目标 | 当前状态 |
| --- | --- |
| 用个人音色朗读 | 部分达成，用户评价音色尚可 |
| 无 GPU 的本地运行 | 已实现 |
| 保存多个音色并复用 | 已实现基础功能 |
| 生成整本书前试听 | 已实现 |
| 已生成内容快速点读 | 本机实测达到约 0.1 秒响应 |
| 边生成边使用已完成内容 | 已实现 |
| 接近 Windows TTS 的新内容生成速度 | **未达成** |
| 整体使用体验满足用户要求 | **未达成，主要问题是速度太慢** |

用户此前对音色的认可，不能理解为对生成速度或整体方案的认可。后续应以最新评价“音色尚可，但是太慢了”为准。

## 六、当前交付范围与未完成事项

- 开发验收针对已配置的本机版本。0.2.0 发布普通阅读器安装包，不包含模型及个人声音资料；尚未制作包含完整声音环境的一体化安装包。
- 模型自动下载与修复尚未提供；运行依赖当前电脑上的模型目录及现有 Aixora 环境。
- MOBI、AZW3 尚未完成个人声音端到端测试；扫描 PDF 未加入 OCR。
- 用户的正式书籍尚未进行整本批量生成，验证使用的是测试资料。
- 音频目前以 WAV 保存，约每小时 165 MiB，长书需要相应磁盘空间。
- 原录音未上传，未进行云端训练，500 元训练预算未动用。

## 七、后续工作的重点

后续应以**降低新内容的生成耗时**为首要目标。现有的音色库、全文索引、任务恢复和缓存播放器可以保留，重点评估声音生成部分是否有足够的提速空间。

任何候选方案都应先在这台电脑上，用同样的文字和音色做小样测试，分别报告音色评价、首次等待时间和每分钟音频的生成耗时。只有速度改善和音色结果都符合用户要求，再决定是否继续投入或动用训练预算。

本报告没有提出已经验证的新提速方案，也不承诺训练后一定能达到 Windows TTS 的速度。
